# GVHMR offline extraction and Mixamo export

The runner uses [zju3dv/GVHMR](https://github.com/zju3dv/GVHMR), revision
`ee960bb6e2ea2d381aa97f08e9b71ef320b624b1`, its released trained networks,
and the repository's neutral low-poly, Mixamo-named mannequin
(`assets/characters/neutral-low-poly.fbx`, 4,810 triangles).
See [character provenance and conversion](../assets/characters/README.md).
It is separate from the browser's MediaPipe solvers.

## Windows setup

Install Git and uv, then run from the repository root:

```powershell
./scripts/setup-gvhmr.ps1 -SmplxModel 'C:/path/to/SMPLX_NEUTRAL.npz'
```

Obtain SMPL-X v1.1 from [the publisher](https://smpl-x.is.tue.mpg.de/) using
your registered account and accepted license. Extract `SMPLX_NEUTRAL.npz`
from the NPZ+PKL archive. The script copies it to
`artifacts/GVHMR/inputs/checkpoints/body_models/smplx/SMPLX_NEUTRAL.npz`.
No account credentials are stored in the scripts or repository.

The public checkpoints come from the Hugging Face mirror used by the
[demo linked in GVHMR's README](https://huggingface.co/spaces/LittleFrog/GVHMR/blob/main/app.py).
Every checkpoint is verified against its SHA256. Downloads resume after
interruption. The licensed body model is not downloaded by the setup script.

The runtime uses Python 3.10, PyTorch 2.3.0/CUDA 12.1, and Blender 4.2.0.
The setup uses the tested dependency versions in `scripts/gvhmr-windows.lock.txt`.
Allow approximately 14 GB for the environment and models, plus working space.
The tested GPU is an RTX 3080 with 12 GB VRAM. The default feature batch size
is four; reduce it with `--batch-size 2` if GPU memory is constrained.

PyTorch3D 0.7.6 is installed without its native extension: inference uses
its Python tensor transforms, and Blender handles character export.
The compatibility patch defers an unused native KNN import, removes an
unused turtle GUI import, and holds the previous camera orientation when
a frame pair has no usable visual features. PyCOLMAP 3.13.0 is used because
the older Windows wheel failed to load on this machine. No trained network
or model weights are changed.

## Process videos

```powershell
# All MP4 sources in videos/
./artifacts/gvhmr-env/Scripts/python.exe scripts/gvhmr_extract.py

# One source
./artifacts/gvhmr-env/Scripts/python.exe scripts/gvhmr_extract.py --video videos/example.mp4

# Only for a camera known to be fixed
./artifacts/gvhmr-env/Scripts/python.exe scripts/gvhmr_extract.py --video videos/example.mp4 --static-camera

# Preserve estimated horizontal travel instead of centered motion
./artifacts/gvhmr-env/Scripts/python.exe scripts/gvhmr_extract.py --video videos/example.mp4 --root-motion travel

# Re-run neural motion inference while reusing detection/features/camera caches
./artifacts/gvhmr-env/Scripts/python.exe scripts/gvhmr_extract.py --video videos/example.mp4 --force-predict
```

The default estimates camera rotation with GVHMR's SimpleVO. Each stage caches
its outputs under `artifacts/gvhmr-runs/<source>-<hash>/<camera-mode>/`.
An unchanged source can resume after a failed stage. Delete that individual
cache directory to deliberately recompute it after changing processing code.
Existing final sidecars are regenerated by an explicit run. `--force-predict`
recomputes the temporal network output. Crop decoding is streamed in batches and
long-sequence attention is evaluated in query chunks with full key/value context,
so these clips fit without dropping frames or shortening the model's context.

Video presentation timestamps are resampled to the model's 30 Hz cadence,
with an exact-duration endpoint in the export. Spatial input resolution is
capped at 960 pixels on the longest edge. The source videos are unchanged.
All temporal samples are processed; there is no excerpt or ten-minute export
limit. GPU/RAM usage still grows with clip length, so the supplied short clips
are the tested scope. A completely black outro holds the last recovered pose
until the original endpoint; its frame count is reported in metadata.

## Outputs beside each source

| Suffix | Contents |
| --- | --- |
| `.gvhmr.fbx` | Neutral skinned mannequin (or `--character` override) and one full-length baked action |
| `.gvhmr.npz` | World-space SMPL-X body pose, shape, root orientation/translation, 22 joint positions/rotations, rest joints, source timestamps, FPS and duration |
| `.gvhmr.json` | Source hash, dimensions, timing, camera mode, model revision, character/body-model hashes and held outro count |
| `.gvhmr.validation.json` | Reimported FBX duration and sampled world-transform export error |

SMPL-X rotations are transferred into the character's actual rest axes for
22 mapped body joints. Root travel is scaled by the character/source leg-length
ratio. The default `--root-motion in-place` centers the hips on both horizontal
world axes **at every frame**, retaining all rotations. Centering only
the first frame left accumulated reconstruction drift in the previous exports.
This intentionally removes horizontal locomotion as well as drift; it is not a
foot-locking correction. Vertical drift is estimated from a centered three-second
20th-percentile envelope of the lowest body joint, smoothed over half a second.
Subtracting that changing floor baseline retains short jumps and crouches while
removing slow vertical float. Clips shorter than three seconds retain their raw
height. This is a heuristic: long airborne movements, stairs and tracking failures
can be interpreted as floor changes. `--root-motion travel` restores both the raw
vertical trajectory and first-frame-origin horizontal travel.
The first root heading is aligned with the character's front; all subsequent turns
and travel receive that same constant yaw rotation. A single constant vertical offset
places the lowest foot position at the character's sole height. This preserves
the corrected trajectory but does not introduce an additional foot-locking solver. The NPZ always
retains the original inferred trajectory, independent of the FBX centering option.
Source finger/face animation is cleared, and those joints remain in their rest
pose. GVHMR estimates body motion, not detailed finger or facial performance.

The tracker chooses the dominant person by accumulated bounding-box area.
Background crowds, occlusion, fast motion, monocular depth ambiguity and camera
estimation can affect reconstruction. FBX validation measures fidelity to the
baked result, not agreement with real-world ground-truth motion capture.

## Export integration check

```powershell
$blender = './artifacts/blender/blender-4.2.0-windows-x64/blender.exe'
& $blender --background --python-exit-code 1 --python tests/gvhmr_retarget_fixture.py
& $blender --background --python-exit-code 1 --python tests/gvhmr_centering.py
& $blender --background --python-exit-code 1 --python tests/gvhmr_fbx_sampling.py
& $blender --background --python-exit-code 1 --python scripts/gvhmr_retarget.py -- --input artifacts/gvhmr-fixture.npz --character 'amsterdam-hackathon/Geo/Chicken Dance.fbx' --output artifacts/gvhmr-fixture.fbx
```

This uses the real character, a turning/translating synthetic skeleton,
and a 1.047-second fractional endpoint. Each production export performs
the same FBX reimport/timing/transform checks automatically, before replacing the
previous deliverable. The centering regression checks both rigs and both root
modes, including nonzero starting coordinates, height changes and turns.
The fractional-duration regression checks the original sample grid and endpoint
for both a short fixture and Real House Dancing's 185.8857-second duration.
The exporter locally adapts Blender 4.2's uniform sampling grid to retain those
original times plus the fractional final key. It fails explicitly if Blender's
sampling implementation changes, rather than silently losing the endpoint.
`scripts/gvhmr_preview.py` uses a fixed camera by default so drift is visible;
pass `--follow-root` only when inspecting traveling animations.

`artifacts/gvhmr-env/Scripts/python.exe tests/gvhmr_memory_test.py` compares
chunked attention against upstream with unmasked, causal and padded inputs.
`artifacts/gvhmr-env/Scripts/python.exe tests/gvhmr_root_motion_test.py` checks
vertical drift removal, short jumps, crouches and short-clip behavior.

## Using saved animations in Pose Studio

Select the matching video, then choose **GVHMR · Saved advanced extraction**
under **Extracted animation → Animation source**, beside Custom and Kalidokit.
The option is available when that video has a matching `.gvhmr.json` and
`.gvhmr.fbx`. Metadata can also name a different local FBX via `fbx_file`;
only a plain `.gvhmr.fbx` filename inside the video directory is accepted.
Refresh the video library after adding files.

After pulling title-named FBXs from another machine, run `npm run import:gvhmr`.
This registers missing metadata using a unique normalized title match (including
local `.info.json` titles), verifies a 65-bone animated Mixamo rig, and checks
animation duration against the local video within 250 ms. It preserves existing
metadata, leaves ambiguous/unmatched files unlinked, and does not rename videos
or duplicate FBXs. Imported metadata records the explicit file mapping and marks
original inference/outro information as unknown.

Some muxed videos outlast their FBX by a few frames. Excerpts hold the final pose
for at most 250 ms to cover that ending and report the hold in the preview note.
Motion timing is not stretched; larger gaps still fail validation.

Choose a bar range or **Complete video** and click **Extract & preview animation**.
GVHMR loads the saved FBX without rerunning MediaPipe or the GPU extraction.
The preview follows the source video clock. Smoothing, motion advance and beat
alignment reuse cached animation; both rotations and hip translation follow
the same time map. FBX and JSON downloads contain the selected processed range,
including an exact fractional closing key. The separate **Download original full
GVHMR FBX** link preserves the untouched full-length extraction.

Preview loading downloads files larger than 8 MiB in 2 MiB HTTP ranges, with
up to ten attempts per chunk and visible byte progress. Interrupted chunks
retry without downloading earlier chunks again; file size and ETag checks prevent
combining different revisions. Switching videos or cancelling stops the requests.
The complete file is still parsed locally, so large clips can take time to prepare
on tablets. `[GVHMR]` browser-console entries distinguish download, parsing and
character-preview failures. The server logs each transfer's time, byte range and
HTTP status; connection failures appear in `logs/server.error.log` when using the
macOS service. There is no application timeout on saved-animation downloads.

The saved extraction uses its original dominant person. Live detection/person
controls do not change it. The main character preview uses the same animation-source selection, and
Compare solvers adds GVHMR beside Custom and Kalidokit for matched videos.
The main preview follows the video clock and uses the original saved motion;
extraction smoothing and timing controls apply to the extracted preview/downloads. Motion signal charts and BCLIP exports still use MediaPipe landmarks
and the live preview's solver; they do not derive measurements from the saved
GVHMR skeleton. JSON makes this explicit with empty landmark frames and unknown
per-frame confidence. No new foot locking or loop-seam blending is applied.
